# 仕様（どの言語で作り直しても、これと同じに動けばよい）

このフォルダは、**今の実装の振る舞いを、そのまま記録したもの**です。Django を別のものに置き換えるときも、
PHP や Node で作り直すときも、ここにある2つの基準に合えば、公開サイトは同じ振る舞いになります。

| 基準 | どこ | 確かめ方 |
|---|---|---|
| **書き出されるHTML** | `golden/`（全ページのHTML） | `python manage.py test spec.test_golden` |
| **公開側の入口（gate）の応答** | `test_gate.py`（HTTP の期待値の表） | `python manage.py test spec.test_gate` |

サンプルのデータは `fixture.py` にあります。作り直した実装に、同じデータを入れて書き出し、`golden/` と**1文字残らず**
同じなら、見た目と中身は同じです。

意図して見た目や仕様を変えたときだけ、`UPDATE_GOLDEN=1 python manage.py test spec.test_golden` で golden を作り直し、
`git diff spec/golden` で、変わったところを目で確かめてから、コミットします。

## 1. 書き出し（静的サイト）の規則

出力は、`public/`（誰でも）と `members/`（ログインした部員）の2つの版です。

| ページ | 公開版 | 部員版 |
|---|---|---|
| `/`（トップ） | ○ | ○ |
| `/about/` | ○ | ○ |
| `/news/`（20件ずつ。2ページ目以降は `?page=N`） | 公開の記事だけ | 部内限定も含む |
| `/news/<id>/` | 公開の記事だけ | 部内限定も含む |
| `/accounts/login/` | ○ | — |
| `/accounts/mypage/` | — | ○（メールは gate が差し込む） |
| `/manuals/`（`?sort=order\|date\|title`）、`/manuals/<id>/` | — | ○ |
| `/videos/`、`/videos/year/<年度>/`、`/videos/<id>/`（年度つきの別版あり） | — | ○ |
| `errors/400,403,404,500.html` | ○ | — |

- **出してはいけないもの**：非公開（`is_active=False`）の記事・マニュアル・動画・ピックアップ。公開版では、部内限定の記事も。
  （`test_golden` が、サンプルの「出てはいけない本文」が公開版に入っていないことを確かめます）
- **編集用のリンクや、管理者向けの部品は、書き出さない。**
- **ファイルの置き場所の規則**：クエリつきのページは `<パス>/_q/<key>-<値>/index.html`（キーは `sort`、`page`、`year` の順。値は英小文字と数字だけ、16文字まで）。
- 同じデータからは、**いつも同じHTML**が出る（時刻や乱数を、出力に混ぜない）。

## 2. 入口（gate）の応答

`test_gate.py` が、本物のPHPサーバーを立てて確かめている内容です。

| リクエスト | 応答 |
|---|---|
| 未ログインで公開ページ | 200、公開版。`Cache-Control: no-cache`、`Vary: Cookie` |
| ログイン済みで任意のページ | 200、部員版があれば部員版、なければ公開版。`Cache-Control: private, no-store` |
| 未ログインで部員専用ページ | 302 → `/accounts/login/?next=<元のURL>`（`no-store`） |
| 有効期限が切れた・未知のセッション | 未ログインと同じ |
| 末尾の `/` がなく、`/` つきのページがある | 301 → `/` つき（クエリも引き継ぐ） |
| 存在しないパス、`..` や `//` を含むパス、`.` で始まるパス | 404（`errors/404.html`） |
| 非公開の記事 | 誰にも 404 |
| `?page=99` のような、書き出していないクエリ | クエリなしのページ。知らないキーは無視 |
| `HEAD` | ヘッダーだけ |
| `/accounts/login/`（ログイン済み） | `?next=` が**サイト内のパスのときだけ**そこへ。`//…`、`https://…`、`\` を含むものは `/` へ |
| `/accounts/logout/` | セッションを消して `/` へ |
| `/accounts/google/login/` | Google の認可URLへ 302（`client_id`、`redirect_uri`、`state`、`nonce`、`hd`=許可ドメイン） |
| `/accounts/google/login/callback/`（ログインを始めていない） | `/accounts/login/` へ戻す |
| `/healthz` | 200 `ok` |
| 公開中の版がない | 503、`Retry-After: 300` |
| **公開版の切り替え（`current` の付け替え）** | **すぐに反映**（古い版を、覚えていてはいけない） |

## 3. 管理画面でできること（機能の一覧）

テストは、各アプリの `tests.py` にあります（全体で200本以上）。作り直すときの、機能の一覧です。

- **記事（ニュース）**：カテゴリ、日付、本文（リッチテキスト。保存のときに、許可した要素だけに絞る）、画像、公開、部内限定
- **ピックアップ**：タイトル、キャッチコピー、画像、リンク先、表示順、公開
- **マニュアル**：Markdown の本文、表示順、公開、更新日時
- **動画**：YouTubeのURL（検証あり）、サムネイル（保存のときにWebPに変換）、グループ、開催日（年度）、字幕の情報
- **プレビューとデプロイ**：入力中の内容でのページのプレビュー、全体のプレビュー、説明つきのデプロイ、過去のバージョンの一覧と、そこへの切り替え
- **システムの状態**：ドメインの期限（サブドメインは、親の期限）、ソフトのサポート終了日
- **メンテナンス**：開始・終了の予定、お知らせ文（Cloudflare への反映は operator）
- **システムの操作**：更新・バックアップ・再起動・ログ・メンテナンス・自動更新のボタン（operator への「依頼」）

## 4. 管理画面と operator の約束（言語に依らない部分）

- 依頼：`spool/requests/<id>.json` → 結果：`spool/results/<id>.json`。受け付ける種類と引数は、`opsd/protocol.py` が唯一の定義。
- メンテナンスの状態：`spool/maintenance.json`。自動更新の状態：`spool/autoupdate.json`。
- 書き出し：`SITE_BUILD_ROOT/releases/vN/` と、公開中を指す `current`（付け替えは、1回の操作で）。
- データ：`state/data/db.sqlite3` と `state/data/media/`。バックアップは、この2つ（と `meta.json`）。
