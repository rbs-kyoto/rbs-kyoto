# 出欠リマインド通知

予定（Schedule）で「出欠を取る」にした予定について、割り当てられた部員のうち**出欠が未回答の人**へ、Web Push で通知します。Web Push の準備（VAPID 鍵の設定など）は `deploy/equipment-reminders.md` と共通です。

## 定期実行

サーバーのスケジューラーから、毎朝1回（例: 毎日8時・日本時間）、次のコマンドを実行します。

```sh
python manage.py send_attendance_reminders
```

アプリと同じ仮想環境・作業ディレクトリで実行してください。

- 通知するのは、予定の開始の**3日前・前日・当日**の回です（`REMINDER_DAYS_BEFORE` で変更できます）。
- **回答済みの人には送りません。** 回答すると、以降の通知は止まります。
- 繰り返し予定は、**回ごと**に判定します。
- 当日の通知は、すでに終了した回には送りません。終日の予定は当日の終わりまで対象です。
- 同じ端末に、同じ回・同じ段階（3日前など）の通知を、二重に送りません（`AttendanceReminderDelivery` に記録します）。
- 届いた通知は、マイページの「通知履歴」に「出欠リマインド」として残ります（端末が複数あっても、1通につき1件です）。
- 通知を受け取れるのは、**Roll 名簿とアカウントが連携している**割当部員だけです。連携していない人には送れません。

送信せずに確認するには `--dry-run` を付けます。

```sh
python manage.py send_attendance_reminders --dry-run
```

## 利用者の設定

マイページの「通知設定」で、端末ごとに「出欠リマインド通知」を有効・無効にできます。**初期状態は無効**です（他の通知と同じく、有効にしたときに確認通知が届きます）。

## 失敗したとき

- VAPID 鍵の設定に問題があるときは、最初の送信で止まり、`Web Push の設定を確認してください` と表示して異常終了します。
- 一部の端末への送信が失敗したときは、残りの端末への送信を続けたうえで、異常終了します。失敗した分は記録されないので、次回の実行で再送します。
- 端末の購読が失効している（404 / 410）ときは、その購読を削除します。
